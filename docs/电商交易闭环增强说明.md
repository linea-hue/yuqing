# 电商平台交易闭环增强说明

本次版本把买家、客服和运营三套工作面统一到一条可追踪的电商业务链路中。页面风格参考综合电商的业务分区，但不复制淘宝/京东的品牌、源码、页面资产或受保护商品图片。

## 买家端

- 商品中心：在售过滤、类目/品牌/店铺筛选、价格区间、排序、规格选择、真实本地商品图片、店铺信息和评价。
- 购物车：按 SKU 行保存规格、数量、店铺、图片和当前可售库存；支持勾选结算、全选、加减、删除和下架/库存不足提示。
- 结算：地址簿 ID、优惠券校验、店铺拆单、商品金额/优惠/运费/应付明细、订单备注、电子发票选项。
- 订单：提交订单幂等、30 分钟待支付关闭窗口、支付幂等、库存预占/扣减、取消释放库存和优惠券、发货、物流、确认收货、订单详情时间线。
- 售后：仅退款、退货退款、换货三种服务类型；退货类售后必须填写寄回运单并由运营仓库验收后才能审批退款。
- 会员：收藏、优惠券领取、地址簿、浏览足迹、已完成订单评价。
- 客服：文字/语音输入、同一安全网关、意图路由和 RAG 引用链路。

## 运营端

- 经营看板：GMV、净收入、客单价、支付转化率、退款率、可售 SKU、库存预占和售后待审均由运行时数据计算。
- 订单履约：订单搜索、状态筛选、店铺拆单信息和发货操作。
- 商品中心：商品发布、改价、上下架、库存调整和图片地址校验；所有操作写审计日志。
- 库存中心：账面库存、订单预占、可售库存及库存流水分开显示，禁止把库存调到已预占数量以下。
- 店铺管理：店铺状态、商品数、成交额、综合/服务/物流评分。
- 逆向物流：查看退货运单、仓库验收，验收状态联动工单 1 的退款审批。
- 审计日志：商品、库存、结算、支付、售后和安全事件统一留痕。
- 知识运营：RAG 文档版本、状态、ACL、临时沙箱上传和检索验证。

## 数据一致性规则

1. 提交结算只创建订单并预占库存，支付成功才扣减账面库存。
2. 待支付订单取消会释放库存预占和已锁定优惠券；支付、下单和售后均支持幂等键。
3. 售后可退金额不超过订单实付减已退款金额，退货退款必须通过逆向物流验收。
4. 商品下架、库存不足、优惠券门槛不满足时，服务端拒绝结算，不能只依赖前端校验。
5. 评价只能来自已完成订单中实际购买的商品，每个订单商品只能评价一次。

## 生产替换点

当前默认是零配置内存适配器，适合简历展示和业务演示。生产落地时应替换为 PostgreSQL/Redis 持久化、真实支付与退款网关、物流平台、对象存储、OCR、WebRTC 流式语音、OIDC/IAM、向量数据库和 OpenTelemetry/Langfuse。
