# 企业级接口与状态约定

## 售后状态机（当前实现）

```text
DRAFT -> SUBMITTED -> RUNNING ->
  COMPLETED (outcome=APPROVED, 自动退款已完成)
  SUSPENDED_HUMAN -> COMPLETED (outcome=APPROVED/REJECTED，人工审批恢复)
  RETRYING -> RUNNING
  DEAD_LETTER -> MANUAL_REPLAY
```

任何高风险状态迁移需要：`case_id + actor_id + actor_role + idempotency_key + trace_id`；当前实现通过 Bearer 令牌解析 actor，并用内存/Redis Checkpoint 适配器保存流程。状态冲突返回 409，不覆盖其他审批结果。

## 响应包统一字段

```json
{
  "request_id": "req_xxx",
  "trace_id": "trace_xxx",
  "code": "OK",
  "message": "success",
  "data": {},
  "degraded": false
}
```

## 发布要求

- OpenAPI 版本化，破坏性变更使用 `/v2`。
- 运营端变更必须带审批人、变更原因、影响范围和回滚版本。
- 所有异步任务可查询 `job_id`，提供重试、取消和死信转人工入口。
- 任何模型输出只能进入结构化 Parser，禁止把原始输出当工具参数执行。
